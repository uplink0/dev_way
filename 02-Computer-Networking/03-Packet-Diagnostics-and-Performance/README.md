# 03. Диагностика пакетов и производительности сети
## 1. Пошаговая декомпозиция HTTP-запроса через тайминги `curl`
Флаг `-w` (`--write-out`) позволяет разложить сетевую задержку на изолированные этапы.
### Фазы запроса:
1. **`time_namelookup` (DNS)**: время разрешения доменного имени.
   * *Аномалия:* > 50-100 мс указывает на проблемы с локальным DNS, `ndots:5` в Kubernetes или перегрузку CoreDNS.
2. **`time_connect` (TCP 3-Way Handshake)**: время установки соединения (`SYN -> SYN-ACK -> ACK`).
   * *Чистое время TCP:* `time_connect - time_namelookup`.
   * *Аномалия:* рост указывает на сетевой RTT, потери пакетов (packet loss) или перегрузку очередей сетевого оборудования.
3. **`time_appconnect` (TLS Handshake)**: время согласования шифрования SSL/TLS.
   * *Чистое время TLS:* `time_appconnect - time_connect`.
   * *Аномалия:* проблемы с производительностью CPU на криптографии, медленная проверка отзывов сертификатов (OCSP).
4. **`time_starttransfer` (TTFB - Time to First Byte)**: время до прихода первого байта тела ответа.
   * *Время работы бэкенда:* `time_starttransfer - time_pretransfer`.
   * *Аномалия:* сеть не виновата — тормозит сам веб-сервер, приложение или база данных.
5. **`time_total`**: общее время от старта до завершения передачи всех данных.

## 2. Анализ сетевого трафика через `tcpdump`
`tcpdump` — инструмент захвата и анализа пакетов на уровне сетевых интерфейсов ядра.
### Золотые правила работы на продакшене:
* Всегда указывать **`-nn`**: запрещает обратный резолвинг IP в домены и портов в имена сервисов (предотвращает шторм DNS-запросов).
* Всегда ограничивать сбор пакетов: флаг `-c <N>` (количество) или BPF-фильтры по порту/хосту.
### Полезные команды:
```bash
# Перехват трафика конкретного порта без DNS-резолвинга
tcpdump -i any -nn port 443
# Перехват только TCP SYN пакетов (попытки подключения)
tcpdump -i any -nn "tcp[tcpflags] & tcp-syn != 0"
# Сохранение дампа в файл для открытия в Wireshark
tcpdump -i eth0 -nn -w /tmp/capture.pcap host 1.2.3.4 and port 80

Специфика туннелей и оверлейных сетей:

  

  
WireGuard (wg0): MTU = 1420 (1500 - 80 байт заголовков IP/UDP/WireGuard).

  
Calico IP-in-IP (tunl0): MTU = 1480 (1500 - 20 байт внешнего IP-заголовка).

  
VXLAN: MTU = 1450 (1500 - 50 байт оверлейных заголовков).

  

  
Патология MTU Black Hole:

  

Если приложение отправляет пакет размером 1500 байт с флагом DF (Don't Fragment) в туннель с MTU 1420, промежуточный роутер должен его отбросить и вернуть ICMP-пакет Fragmentation Needed (Path MTU Discovery).

  Если фаервол блокирует этот ICMP-пакет:


  

  
TCP-рукопожатие проходит успешно (пакеты SYN маленькие).

  
Но при попытке передать большой объем данных (SSL-сертификат, HTTP Body) соединение зависает намертво без явных ошибок.
