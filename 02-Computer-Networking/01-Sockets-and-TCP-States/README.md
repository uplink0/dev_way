# Тема 2.1. Сетевые сокеты, утилита ss и состояния TCP: TIME_WAIT vs CLOSE_WAIT
# 1. Что такое сетевой сокет (Network Socket)?
Сокет в Linux — это программная абстракция (файл/дескриптор), идентифицируемая пятеркой параметров (**5-tuple**):
1. **Протокол:** TCP или UDP
2. **IP-адрес источника (Source IP)**
3. **Порт источника (Source Port)**
4. **IP-адрес назначения (Destination IP)**
5. **Порт назначения (Destination Port)**

# 2. Ключевая дуэль собеседований: TIME_WAIT vs CLOSE_WAIT
```text
  Клиент (Active Close)                 Сервер (Passive Close)
         |                                         |
         | -------- FIN (Я закрываю) ------------> |
         | <------- ACK (Понял, закрывай) -------- |  (Переходит в CLOSE_WAIT)
         |                                         |  (Сервер должен закрыть сокет)
         | <------- FIN (Я тоже закрыл) ---------- |
(Переходит в TIME_WAIT)                            |
         | -------- ACK (Всё, пока!) ------------> | (Закрыт)
         |
  [Ждет 2*MSL (60 сек)]
         |
      (Закрыт)

Состояние	Кто виноват			Причина	Как лечить
TIME_WAIT	Сетевой стек TCP (норма).	Сокет ждёт 60 секунд на стороне инициатора разрыва, чтобы запоздалые пакеты не попали в новое соединение.	Если сокетов слишком много: включить keepalive в веб-сервере и параметр ядра sysctl net.ipv4.tcp_tw_reuse=1.
CLOSE_WAIT	Разработчик (баг в коде)!	Приложение получило сигнал закрытия от клиента, но не вызвало socket.close(). Висит бесконечно.	Баг-репорт разработчикам (утечка сокетов). Временное решение: рестарт зависшего процесса.
 
# 3. Практическая диагностика с помощью ss

```bash
# 1. Посмотреть все слушающие порты TCP/UDP с процессами:
ss -tulnp
# 2. Сводная статистика по всем сокетам на сервере (число TCP, TIME_WAIT):
ss -s
# 3. Найти все соединения в статусе TIME_WAIT:
ss -tan state time-wait
# 4. Найти все зависшие соединения в статусе CLOSE_WAIT:
ss -tan state close-wait
# 5. Посчитать количество соединений по каждому статусу:
ss -ant | awk '{print $1}' | sort | uniq -c | sort -nr
