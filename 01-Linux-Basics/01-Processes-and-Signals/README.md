Тема 1.1. Процессы в Linux, сигналы и Load Average
# 1. Жизненный цикл и состояния процессов
Каждый процесс в Linux представлен записью в таблице процессов ядра и виртуальной директорией `/proc/<PID>/`.
Ключевые состояния (Process States):
* `R` (Running / Runnable): выполняется на CPU или ожидает квант времени в `runqueue`.
* `S` (Interruptible Sleep):** процесс ожидает события/таймера, мгновенно прерывается сигналами.
* `D` (Uninterruptible Sleep):** процесс заблокирован ожиданием ответа аппаратуры/диска (I/O). **Нельзя убить даже через `kill -9`**!
* `Z` (Zombie / Defunct):** процесс завершился (`exit()`), освободил память, но родитель (`PPid`) не вызвал `wait()`/`waitpid()`. Чтобы устранить зомби — нужно завершить или перезапустить его родительский процесс.
* `T` (Stopped):** процесс остановлен/заморожен сигналом `SIGSTOP` или комбинацией клавиш `Ctrl+Z`. Не потребляет CPU, но удерживает сокеты и память. Для возобновления работы требует сигнала `SIGCONT`.

# 2. Сигналы Linux (Signals): SIGTERM vs SIGKILL vs SIGSTOP/SIGCONT
| Сигнал | Номер | Поведение | Назначение в DevOps |

| SIGTERM | `15` | Мягкое завершение. Процесс может перехватить сигнал, завершить транзакции БД, закрыть сокеты и выйти без повреждения данных. | Стандартный сигнал Kubernetes при остановке пода (`terminationGracePeriodSeconds: 30`). |
| SIGKILL | `9` | Принудительное уничтожение ядром. Процесс **не может перехватить или проигнорировать** этот сигнал. | Используется как крайняя мера, если сервис завис. Риск повреждения незаписанных данных. |
| SIGHUP  | `1` | Hangup. Обрыв терминала. Демоны (Nginx, Prometheus) используют для перечитывания конфигов без рестарта (`nginx -s reload`). |
| SIGSTOP | `19` | Принудительная заморозка (пауза) процесса ядром. Нельзя перехватить. Состояние переходит в **`T`**. | Приостановка фоновых задач, отладка, инциденты зависания. |
| SIGCONT | `18` | Разморозка (возобновление выполнения) процесса из состояния `T`. | Возврат замороженных процессов к штатной работе. |
---
## 3. Load Average vs Загрузка CPU (%)
* **Load Average** — среднее число процессов, находящихся в состоянии `R` (работа на CPU) плюс процессов в состоянии `D` (ожидание I/O диска).
* Числа `LA: 1.0, 5.0, 15.0` оцениваются относительно числа процессорных ядер (`nproc`):
  * Если `nproc = 2`, а `LA = 2.0` — система утилизирована на 100%.
  * Если `LA > nproc` — формируется очередь ожидания.
* **Почему LA высок при низком CPU %:**  
  Если диск не успевает обрабатывать запросы (высокий I/O wait), процессы блокируются в статусе `D`. CPU свободен, но очередь задач огромна.

🛠️ Шпаргалка команд для диагностики:
```bash
nproc                                   # Количество ядер CPU
cat /proc/loadavg                       # Текущий Load Average и число активных потоков
ps aux --sort=-%cpu | head              # Топ процессов по CPU
ps aux --sort=-%mem | head              # Топ процессов по памяти
ps -eo pid,ppid,stat,cmd | grep -w 'Z'  # Поиск Zombie-процессов
ps -eo pid,stat,cmd | awk '$2 ~ /T/ {print}' # Поиск замороженных процессов (состояние T)
kill -15 <PID>                          # Graceful shutdown (SIGTERM)
kill -9 <PID>                           # Форсированное уничтожение (SIGKILL)
kill -STOP <PID>                        # Заморозить процесс (SIGSTOP, код 19)
kill -CONT <PID>                        # Разморозить процесс (SIGCONT, код 18)

1. Поиск процессов (по имени, портам и проблемным состояниям)
bash
# --- Быстрый поиск по имени ---
pgrep -a -l <имя>                      # Найти PID и вывести полную команду запуска (без мусора grep)
pidof <имя_бинарника>                  # Быстро получить только PID (например: pidof nginx)
ps -C <имя_команды> -o pid,user,%cpu,%mem,cmd # Фильтр ps по имени исполняемого файла
# --- Поиск процессов в зависших состояниях (D и Z) ---
ps -eo pid,stat,wchan:20,cmd | awk '$2 ~ /D/ {print}' # Поиск процессов в состоянии D (I/O wait)
ps -eo pid,ppid,stat,cmd | awk '$3 ~ /Z/ {print}'     # Поиск зомби (Z) с их родителями (PPID)
# --- Поиск процесса, занявшего сетевой порт ---
ss -tulpn | grep :<PORT>               # Найти, кто слушает порт (выведет pid=... и имя)
lsof -i :<PORT>                        # Альтернатива: процесс, открывший соединение/порт
fuser -v <PORT>/tcp                    # Быстрый поиск PID по номеру TCP-порта
2. Связи PID и PPID (Дерево процессов и поиск виновников)

Если процесс завис или породил зомби — нужно исследовать его предков и потомков.

bash
# --- Поиск предков и родителей ---
ps -o ppid= -p <PID>                   # Быстро узнать PPID (PID родителя) для указанного процесса
pstree -aps <PID>                      # Дерево предков и потомков процесса (видно всю цепочку до init/systemd)

# --- Поиск дочерних процессов (по PPID) ---
pgrep -P <PPID> -a                     # Найти всех прямых детей родительского процесса
ps --ppid <PPID> -o pid,stat,cmd       # Список всех процессов-потомков для PPID

# --- Определение принадлежности к cgroup / systemd ---
systemctl status <PID>                 # К какому systemd-юниту/сервису принадлежит PID
cat /proc/<PID>/cgroup                 # Cgroup процесса (позволяет понять, в каком контейнере/поде запущен)

# 3. Исследование «под капотом» через /proc/<PID>/

Виртуальная файловая система /proc хранит абсолютную правду о процессе, даже если он пытается замаскироваться.

bash
# --- Откуда и с чем запущен ---
ls -l /proc/<PID>/exe                  # Реальный симлинк на бинарный файл (полезно при атаках/майнерах)
ls -l /proc/<PID>/cwd                  # Рабочая директория (откуда стартовал процесс)
cat /proc/<PID>/cmdline | tr '\0' ' '  # Полная строка запуска со всеми скрытыми аргументами и флагами
echo ""
# --- Переменные окружения и конфиги ---
cat /proc/<PID>/environ | tr '\0' '\n' # Все ENV-переменные процесса (токены, конфиги, параметры БД)

# --- Лимиты и статус ресурсов ---
cat /proc/<PID>/status                 # Детальный статус: VmRSS (память), Threads, State, Uid/Gid
cat /proc/<PID>/limits                 # Лимиты процесса (max open files, memory limit и т.д.)

# 4. Файлы, сеть и потоки (Threads)
bash
# --- Открытые дескрипторы (файлы, сокеты, пайпы) ---
ls -l /proc/<PID>/fd                   # Список всех открытых файловых дескрипторов
ls -l /proc/<PID>/fd | wc -l           # Сколько файлов/сокетов удерживает процесс (проверка на утечку fd)
lsof -p <PID>                          # Подробный список открытых процессом файлов, библиотек и сокетов

# --- Сетевые соединения конкретного PID ---
ss -tp | grep "pid=<PID>,"             # Все активные сетевые сокеты именно этого процесса

# --- Потоки (нити / threads) ---
ps -T -p <PID>                         # Список всех тредов процесса (SPID / TID)
top -H -p <PID>                        # Мониторинг нагрузки по отдельным тредам внутри одного процесса

#5. Deep Debugging: Что процесс делает прямо сейчас?

Критично для диагностики высоких Load Average и процессов в состояниях D или R.

bash
# --- Почему процесс в состоянии D (I/O wait)? ---
cat /proc/<PID>/wchan                  # В какой функции ядра ожидает процесс (например: wait_on_page_bit, nfs_*)
cat /proc/<PID>/stack                  # Стек вызовов ядра (показывает, на какой именно дисковой/сетевой операции блокировка)

# --- Нагрузка на диск (I/O) конкретным процессом ---
cat /proc/<PID>/io                     # Статистика прочитанных и записанных байт на диск (rchar, wchar, read_bytes)
iotop -p <PID>                         # I/O активность процесса в реальном времени

# --- Трассировка системных вызовов (Syscalls) ---
strace -p <PID>                        # Что делает процесс прямо сейчас (открытие файлов, чтение из сокетов)
strace -c -p <PID>                     # Собрать статистику по системным вызовам (нажмите Ctrl+C для сводной таблицы)
