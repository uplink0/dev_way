# Тема 1.5. Профессиональная автоматизация на Bash: Строгий режим и обработка ошибок

# 1. Строгий режим: `set -euo pipefail`
По умолчанию Bash крайне снисходителен к ошибкам, что в продакшене приводит к неконтролируемым авариям.
Золотой стандарт любого DevOps-скрипта — строка в начале:

```bash
set -euo pipefail
 
# Флаг	Полное имя	Что делает	Какую аварию предотвращает
-e	errexit	Прерывает выполнение скрипта при ненулевом коде возврата любой команды.	Не даст выполниться команде удаления rm -rf *, если предыдущая команда cd /app упала.
-u	nounset	Вызывает падение скрипта при попытке прочитать неинициализированную переменную.	Защищает от выполнения rm -rf /data/${UNDEFINED_VAR}/*.
-o pipefail	pipefail	Считает весь пайплайн cmd1 | cmd2 ошибочным, если упала хотя бы одна команда цепочки.	По умолчанию Bash смотрит только на код последней команды, игнорируя падение левой части пайпа.
-x (опция)	xtrace	Выводит каждую исполняемую строку в терминал (режим трассировки).	Незаменим при отладке в CI/CD раннерах.
 
# 2. Гарантированная очистка ресурсов через trap

Конструкция trap перехватывает сигналы завершения и выполняет переданную функцию даже при ошибке (EXIT), нажатии Ctrl+C (SIGINT) или SIGTERM.
  
```bash
TMP_DIR=$(mktemp -d)
# Функция очистки:
cleanup() {
    rm -rf "${TMP_DIR}"
    echo "Временные файлы удалены"
}
# Навешиваем ловушку:
trap cleanup EXIT INT TERM
 
# 3. Перенаправление потоков ввода-вывода (I/O Redirection)
  
0: stdin (стандартный ввод).
  
1: stdout (стандартный вывод).
 
2: stderr (поток ошибок).
  
``` bash
# Глушим и стандартный вывод, и ошибки:
command > /dev/null 2>&1

# или в современном Bash:
command &> /dev/null

# Запись stdout в файл, а stderr в терминал:
command 1> output.log

# Дописывание в конец файла (append):
command >> output.log 2>&1

# 4. Разница "$@" vs "$*"
  
# "$@" — сохраняет каждый входящий аргумент в отдельной кавычке: "$1" "$2" "$3" (безопасно для путей с пробелами).
 
# "$*" — сливает все аргументы в одну общую строку: "$1 $2 $3".
