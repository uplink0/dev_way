# Тема 1.2. Оперативная память в Linux, Buffers, Cache, Swap и OOM-Killer
## 1. Разница между free, buff/cache и available
В выводе команды `free -m`:
* **`used`:** память, фактически занятая процессами приложения.
* **`free`:** полностью неиспользуемая память. В Linux свободная память отдаётся под кэш.
* **`buff/cache`:** 
  * `Buffers` — метаданные файловых систем и буферы блочных устройств.
  * `Cached` (Page Cache) — страницы прочитанных с диска файлов. При необходимости ядро мгновенно освобождает их.
* **`available`:** реальный объём памяти, доступный для запуска новых процессов без ухода в Swap.
> 💡 **Правило DevOps:** Сервер не испытывает проблем с памятью, пока показатель `available` находится в безопасной зоне, даже если `free` равен 100 МБ.
---
## 2. Поведение Swap и параметр swappiness
* **Swap** — область подкачки на диске для сброса неактивных страниц RAM.
* **`/proc/sys/vm/swappiness` (от 0 до 100):**
  * `60` — стандартное значение Linux (сбалансированный сброс).
  * `0` — сбрасывать в Swap только при критической угрозе OOM.
* **Почему Swap отключают в Kubernetes:**  
  Чтобы Kubelet гарантировал соблюдение лимитов `resources.limits.memory` и предсказуемое поведение подов без неконтролируемой деградации диска I/O.
---
## 3. Анатомия OOM-Killer (Out of Memory)
Когда физическая память и Swap исчерпаны, ядро активирует механизм OOM-Killer:
1. Вычисляет **`oom_score`** для каждого процесса (от 0 до 1000). Чем больше RAM ест процесс относительно общего объема, тем выше балл.
2. Процесс с наивысшим баллом уничтожается сигналом **`SIGKILL` (код 137)**.
3. Корректировка приоритета: через файл `/proc/<PID>/oom_score_adj` (значение `-1000` полностью защищает процесс от расстрела).

## 🛠️ Шпаргалка команд для диагностики:
```bash
free -m                                      # Сводка по памяти в мегабайтах
cat /proc/meminfo                            # Детальные счётчики памяти ядра
ps aux --sort=-%mem | head -n 10             # Топ-10 процессов-пожирателей памяти
dmesg -T | grep -i -E 'oom[-_]killer|killed process' # Поиск следов OOM в логах ядра
journalctl -k --grep="Out of memory"         # Поиск OOM в системном журнале
cat /proc/<PID>/oom_score                    # Проверить риск расстрела процесса
